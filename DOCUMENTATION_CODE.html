📘 Documentation Technique — TP Vérificateur d'Anagrammes

Application web complète en PHP, MySQL (PDO), HTML5/CSS3 avec gestion des utilisateurs et historique personnel.

🔐 Sécurité appliquée : mots de passe hashés (password_hash / password_verify), un seul compte par inscription, déconnexion simple (session détruite, compte conservé), historique personnel lié à l'utilisateur authentifié.

2. Connexion à la base de données — config.php

config.php

Ce fichier initialise la session PHP et établit la connexion PDO à MySQL. L'utilisation de PDO avec des requêtes préparées protège contre les injections SQL.

<?php
session_start();

$host = 'localhost';
$dbname = 'tp_anagramme';
$username = 'root';
$password = '';

try {
    $pdo = new PDO(
        "mysql:host=$host;dbname=$dbname;charset=utf8mb4",
        $username,
        $password,
        [
            PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_EMULATE_PREPARES   => false,
        ]
    );
} catch (PDOException $e) {
    die("Erreur de connexion : " . $e->getMessage());
}

define('BASE_URL', '/tp-anagramme/');
?>

Lignes clés :

  • session_start() : démarre la session pour maintenir l'état de connexion (exigence 4.5).
  • new PDO(...) : connexion sécurisée avec encodage UTF-8 et gestion d'erreurs.

3. Fonctions utilitaires — functions.php

functions.php

Regroupe toutes les fonctions réutilisables par l'application.

3.1 Algorithme d'anagramme

function isAnagram(string $s1, string $s2): bool
{
    $clean1 = strtolower(str_replace(' ', '', $s1));
    $clean2 = strtolower(str_replace(' ', '', $s2));

    if (strlen($clean1) !== strlen($clean2)) {
        return false;
    }

    $arr1 = str_split($clean1);
    $arr2 = str_split($clean2);
    sort($arr1);
    sort($arr2);
    return $arr1 === $arr2;
}

Lignes clés :

  • strtolower + str_replace(' ', '', ...) : normalise les chaînes (minuscules, sans espaces).
  • strlen : élimine rapidement les chaînes de longueurs différentes.
  • str_split + sort : trie les caractères pour comparer les tableaux.
  • Complexité temporelle : O(n log n), espace : O(n).

3.2 Validation des chaînes

function isValidString(string $s): bool
{
    return preg_match('/^[a-zA-Z0-9À-ÿ\s]*$/', $s) === 1;
}

Vérifie que la saisie ne contient que lettres, chiffres et espaces (exigence 2.5).

3.3 Helpers de session et redirection

function isLoggedIn(): bool { return !empty($_SESSION['user_id']); }
function requireLogin(): void { if (!isLoggedIn()) { redirect(BASE_URL . 'login.php'); exit; } }
function redirect(string $url): void { header("Location: $url"); exit; }

4. Inscription — register.php

register.php

Le formulaire demande Pseudonyme, Mot de passe, Confirmation (exigence 4.1). Les validations vérifient les champs vides, la longueur du pseudo, la correspondance des mots de passe (exigence 4.2).

Hashage du mot de passe

$passwordHash = password_hash($password, PASSWORD_DEFAULT);

$stmt = $pdo->prepare('INSERT INTO users (pseudo, password) VALUES (?, ?)');
$stmt->execute([$pseudo, $passwordHash]);

Ligne clé : password_hash() crée un hash sécurisé (bcrypt par défaut). Le mot de passe en clair n'est JAMAIS stocké en base (exigence sécurité renforcée).

5. Authentification — login.php

login.php

Le formulaire de connexion vérifie le pseudo et le mot de passe (exigence 4.4).

Vérification du hash

$stmt = $pdo->prepare('SELECT id, pseudo, password FROM users WHERE pseudo = ?');
$stmt->execute([$pseudo]);
$user = $stmt->fetch();

if ($user && password_verify($password, $user['password'])) {
    $_SESSION['user_id'] = $user['id'];
    $_SESSION['pseudo'] = $user['pseudo'];
    redirect(BASE_URL . 'index.php');
}

Lignes clés :

  • password_verify() : compare le mot de passe saisi avec le hash stocké.
  • $_SESSION['user_id'] et $_SESSION['pseudo'] : stockent l'état de connexion (exigence 4.5).

6. Déconnexion — logout.php

logout.php
if (isLoggedIn()) {
    session_destroy();
}
redirect(BASE_URL . 'login.php');

Ligne clé : session_destroy() met fin à la session (exigence 4.6). Le compte reste en base de données.

7. Vérificateur d'anagrammes — index.php

index.php

L'accès au vérificateur est libre (pas de connexion requise pour vérifier). L'enregistrement en base est conditionnel à l'authentification.

Traitement du formulaire

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $string1 = trim($_POST['string1'] ?? '');
    $string2 = trim($_POST['string2'] ?? '');

    if ($string1 === '' || $string2 === '') {
        $error = 'Veuillez remplir les deux champs.';
    } elseif (!isValidString($string1) || !isValidString($string2)) {
        $error = 'Caractères non autorisés.';
    } else {
        $result = isAnagram($string1, $string2);

        if ($isLoggedIn) {
            $stmt = $pdo->prepare(
                'INSERT INTO verifications (user_id, string1, string2, is_anagram) VALUES (?, ?, ?, ?)'
            );
            $stmt->execute([
                $_SESSION['user_id'],
                $string1,
                $string2,
                $result ? 1 : 0,
            ]);
        }
    }
}

Lignes clés :

  • isAnagram($string1, $string2) : détermine le résultat (exigence 2.3).
  • if ($isLoggedIn) : n'enregistre que si l'utilisateur est connecté (exigence 4.7).
  • user_id : lie chaque vérification au compte authentifié.

8. Historique personnel — history.php

history.php

L'accès est protégé (requireLogin()). Le tableau affiche uniquement les vérifications de l'utilisateur connecté (exigence 3.4 et 4.7).

requireLogin();

$stmt = $pdo->prepare(
    'SELECT string1, string2, is_anagram, created_at 
     FROM verifications 
     WHERE user_id = ? 
     ORDER BY created_at DESC'
);
$stmt->execute([$_SESSION['user_id']]);
$verifications = $stmt->fetchAll();

9. Base de données — database.sql

database.sql
CREATE TABLE IF NOT EXISTS users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    pseudo VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS verifications (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    string1 VARCHAR(255) NOT NULL,
    string2 VARCHAR(255) NOT NULL,
    is_anagram TINYINT(1) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB;
TableChamps importants
usersid, pseudo, password (hashé)
verificationsuser_id (clé étrangère), string1, string2, is_anagram, created_at

10. Flux global de l'application

  1. L'utilisateur arrive sur index.php sans être connecté → il peut vérifier des anagrammes librement.
  2. Après vérification, un message l'invite à se connecter pour enregistrer et consulter son historique.
  3. S'il s'inscrit (register.php) ou se connecte (login.php), une session est créée.
  4. Toute vérification effectuée connecté est enregistrée dans verifications avec son user_id.
  5. L'historique (history.php) filtre par user_id : chaque utilisateur voit uniquement ses propres vérifications.
  6. La déconnexion (logout.php) détruit la session uniquement.
